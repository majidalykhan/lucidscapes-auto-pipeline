# Lucidscapes — Autonomous Cozy-Cinematic Video Pipeline

A fully autonomous ComfyUI pipeline that generates original cozy/cold
ambient cinematic video clips end to end — no human ever writes a prompt.
Every run invents its own scene, renders it, animates it, and finishes it,
unattended, on a single local GPU.

```
python -m runner.pipeline run --limit 10
```

...and ten brand-new, never-before-seen cozy cinematic clips come out the
other end in `output/FINAL/`.

## What it actually does

Six stages, one job at a time, each running a different local model:

1. **Invent a scene.** A vision-language model (Qwen3-VL) writes an
   original still-image prompt from scratch — no topic, no seed idea, no
   human input of any kind.
2. **Render the still.** Flux 2 Dev turns that prompt into a photoreal
   frame.
3. **Describe the motion.** Qwen3-VL looks at the *actual rendered image*
   (not the text prompt) and writes a motion instruction based on what it
   can see — what should drift, what should stay locked.
4. **Animate it.** WAN 2.2 image-to-video turns the still into a 5-second
   clip, camera direction included.
5. **Upscale.** SeedVR2 cleans up and upscales the raw generation.
6. **Interpolate.** RIFE doubles the frame rate for a smoother, more
   cinematic final result.

Nothing in that chain is scripted content — every prompt at every stage is
generated by a model looking at the previous stage's actual output.

## Why this is harder than it sounds

Small local vision-language models are not naturally good at "be creative
and vary yourself." Two failure modes showed up repeatedly during
development, and both needed the same fix:

- **Scene collapse.** Left to invent freely, the model kept returning to
  the same handful of scenes (a cabin in the snow, over and over), even
  with an explicit instruction to vary the subject.
- **Camera collapse.** Given six possible camera directions to choose
  from, the model defaulted to the same one in 9 out of 10 generations,
  regardless of the image or the instruction wording.

**The fix, in both cases: stop asking the model to choose, and force the
choice in code instead.** A small Python layer randomly assembles a
concrete scene brief (subject + weather + terrain + lighting accents) and
a camera direction *before* calling the model, and requires the model to
build its output around that exact assignment. A lightweight
keyword-adherence check catches the rare case where the model still drifts
back to its own default, and silently retries once with a fresh seed. No
manual review, no scoring model, no human in the loop — just a
deterministic safety net around a probabilistic model.

Other real engineering problems solved along the way:

- **Output consolidation.** Every exported ComfyUI workflow originally
  saved to a different personal folder scattered across the filesystem.
  All four media-producing stages now get their save path overridden at
  runtime, and a cleanup sweep runs after every job so nothing accumulates.
- **Silent completion detection.** One of the text-generation stages
  reports zero output data through ComfyUI's normal job-status API, even
  on a totally successful run — confirmed by reading the node's source,
  not by guessing. The runner had to learn a second way to recognize "this
  job actually finished."
- **Structured prompt chaining.** A small templating layer lets one
  stage's output become a named variable (`{image_prompt}`, `{scene_brief}`,
  `{camera_move}`) that a later stage's instruction references directly,
  without a human ever touching either value.

## Architecture

```
runner/
  pipeline.py        — orchestrates the 6-stage run, forces scene/camera
                        variety, retries on drift, manages the ledger
  comfy_client.py     — HTTP + websocket client for ComfyUI's own API
mcp/
  lucid_mcp.py        — optional MCP server for manual/interactive use
                        (not involved in the autonomous pipeline)
workflows/            — the exported ComfyUI graphs, one per stage
config.yaml           — stage order, node wiring, per-stage overrides
```

All actual generation settings — resolution, steps, CFG, sampler, model
checkpoints — live inside the exported ComfyUI workflow JSONs, edited in
ComfyUI's own UI and re-exported. `config.yaml` only wires runtime values
(prompts, seeds, file paths) into the right node on the right stage.

## Requirements

- A local [ComfyUI](https://github.com/comfyanonymous/ComfyUI) install with:
  Qwen3-VL (via the `ComfyUI-QwenVL` node pack), Flux 2 Dev, WAN 2.2,
  SeedVR2, and RIFE, plus their usual dependency node packs
  (Video Helper Suite, Comfyroll's text-save node, Pixaroma).
- Python 3.10+ with `requirements.txt` installed.
- A GPU with enough VRAM to run each model in turn — this was built and
  tested on a single RTX 5090 (~34 GB). Models are unloaded from VRAM
  between every stage, so peak usage is one model at a time, not all six.

## Running it

```bash
pip install -r requirements.txt

# sanity-check every workflow/config wiring before a real run
python -m runner.pipeline check

# generate N brand-new videos, fully unattended
python -m runner.pipeline run --limit 10

# check GPU/queue/ledger status at any time
python -m runner.pipeline status
```

Finished videos land in `output/FINAL/`. Nothing else needs to be supplied
— there's no prompt file to fill in for the autonomous flow.
